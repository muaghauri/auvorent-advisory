## 1. Executive summary

Auvorent Advisory is an intended business-first advisory practice for owners, CEOs, and operations leaders. Its central value proposition is **business clarity, measurable improvement, and a trusted consulting relationship**. AI, automation, and predictive analytics are selected when they serve an established business objective; they are not positioned as the product in themselves.

The V6 website has 17 public-content routes, two draft legal routes, and a custom 404 page. It is built as pre-rendered HTML with shared CSS and JavaScript and has an optional Cloudflare Pages contact-form function. It does **not** yet contain an operational CMS, database, admin authentication, or content-management APIs.

### Intended initial commercial focus (proposed; not independently validated)

- **Primary geography:** United States, English language.
- **Decision-makers:** Owners, CEOs, managing directors, and operating leaders at established B2B service firms with approximately 15–150 employees.
- **Priority sectors:** Business and professional services, marketing agencies, managed services/IT service providers; staffing and recruitment as a narrower secondary use case.
- **Entry engagement:** A scoped Business Performance Diagnostic, proposed at approximately 10 business days once client access is available.
- **Indicative internal pricing hypothesis:** US$4,500–7,500 for the diagnostic, pending validation and approval; **not** a published commitment.
- **Commercial journey:** Strategy inquiry → discovery → evidence-based diagnostic → separately scoped improvement/AI implementation → optional advisory retainer.

**Do not assume every existing config field is already connected to the rendering engine.** The next architectural task is to make the content-source contract authoritative across every page and section, without changing the approved frontend design.

## 6. Business Optimization Check

- Standalone client-side assessment at `/assessment/`.
- Seven questions cover business challenge, repetitive work, KPI visibility, AI adoption, data quality, improvement ownership and desired outcomes.
- Provides a **preliminary area to investigate** and practical next steps, not a verified root-cause diagnosis or an unsupported numerical readiness score.
- A visitor who elects to discuss the result is taken to `/contact/?from=assessment/`-style handoff logic (actual redirect: `/contact/?from=assessment`); a summary is temporarily transferred using browser `sessionStorage` and prefilled into the contact message.
- Answers are not currently written to a backend assessment database.

**CMS implications:** Question content, answer options, summary templates, disclaimers, related CTA and artwork should become controlled, versioned entities. Do not convert the screening output into a purported factual diagnosis.

## 7. Contact form and email-delivery contract

**Page:** `/contact/`  
**Frontend endpoint:** `POST /api/contact`  
**Current backend:** Cloudflare Pages Function in `functions/api/contact.js`, using Resend when configured.

| User input | Current requirement |
|---|---|
| Full name | Required; minimum length is validated server-side |
| Work email | Required; server-side format check |
| Company | Required |
| Team size | Required from predefined ranges |
| Main priority | Required from predefined choices |
| Business challenge | Required; minimum 20 characters server-side |
| Contact consent | Required; expected submitted value `on` |
| Hidden `website` field | Honeypot for basic bot filtering |

**Configured destination:** `muaghauri@gmail.com` (via `CONTACT_TO`, with that address as the endpoint fallback). The sender must be a **verified** domain address in `CONTACT_FROM`; an actual `RESEND_API_KEY` must be set. These are server-side secrets, not editable public frontend strings.

**Response behavior:** The endpoint validates origin and fields, optionally verifies Cloudflare Turnstile **only when both the secret and frontend widget are configured**, submits through Resend, and returns success only following a successful provider response. A missing email configuration returns HTTP 503; delivery errors return HTTP 502. No database persistence of inquiries is implemented in V6.

**Critical local-preview limitation:** `python3 -m http.server` serves static files only. It cannot execute the Cloudflare Pages Function, so the contact form **will not send email on localhost**. Email must be configured and tested on the target hosting environment (or a compatible local Functions development server).

## 8. SEO and accessibility baseline

V6 includes per-page `<title>` and meta descriptions, logical page headings, canonical URLs, Open Graph metadata with PNG image, Twitter summary image metadata, organization/webpage/article JSON-LD as applicable, an XML sitemap, and a robots file. Navigation includes a skip link and an accessible mobile-menu toggle. The design includes focus styling and a reduced-motion media query.

**Indexing status:** The default generated site is staging-only (`noindex,nofollow`, `robots.txt` disallows crawlers). The canonical base defaults to the **proposed** `https://auvorent.com` and must be set to the approved production domain before launch. The presence of SEO tags does not mean the site has been submitted, indexed, or independently audited for keyword performance.

**CMS requirement:** Every indexable page and article must have separately editable title, meta description, canonical slug, social title/description/image, structured-data fields where supported, indexability, and publication date. Sitemap generation and internal-link checks must run after every publication.

## 9. Local setup, tests, and hosting

From the extracted package root:

```bash
cd auvorent-website-v6
python3 build.py
python3 -m http.server 8787 --directory site
# Visit http://localhost:8787
```

**Do not open** nested `site/.../index.html` through `file://`; absolute `/assets/...` references require a server origin.

Run existing tests:

```bash
python3 -m unittest discover -s tests -v
node tests/contact.test.mjs
# Or run both using npm test, if Node.js 18+ is available.
```

The reviewed V6 package passed all five Python structural/launch-gate tests and the Node.js contact-handler checks in this documentation review. These are not substitutes for final real-device testing, production email verification, Lighthouse, or a penetration/security review.

**Recommended V6-compatible host:** Cloudflare Pages; build command `python3 build.py`; output directory `site`; keep `functions/` at the project root. GoDaddy can remain the domain registrar. Uploading only `site/` to ordinary static hosting will **not** deploy the existing Cloudflare contact function.

## 10. Proposed CMS/Admin architecture — next phase, NOT in V6

Preserve the fast, SEO-friendly static-public-site output while making content fully manageable through a separate authenticated application. A publish action should validate the content, generate a fresh static build, and deploy or promote an approved version. A live content API is an alternative for selected non-SEO-critical components, but should not force client-side-only rendering of primary page text.

### Required editable resources

| Resource | Editable properties |
|---|---|
| Site settings | Brand name, logos, favicon, colors subject to approved theme limits, social profiles, legal and contact details |
| Email and forms | Recipient(s), reply-to policy, form headings, fields, options, consent text and routing settings; provider API keys remain encrypted server-side |
| Pages | URL slug, status, template, page-level SEO, preview/publish history |
| Page sections | Order, enable/disable, heading, subheading, rich text, CTA, background, media, icon, layout variant |
| Services | Title, slug, overview, service details, icons, outcomes, related pages |
| Industries | Name, slug, problems, opportunities, relevant services and imagery |
| Insights | Draft/review/published article, excerpt, image, author only when verified, publication date, tags, metadata |
| Media library | Upload, alt text, caption, mime type, dimensions, assignment and replacement tracking |
| Navigation | Header/footer links, order, labels, CTA text and destinations |
| Assessments | Questions, options, conditional summaries, CTA and required disclaimers |
| Inquiry records | Submission intake, read/unread status and authorized retention/export rules, if approved |
| Users and audit log | Admin/editor roles, authentication, change history, version rollback and approval trail |

These routes need clear authentication/authorization, input validation, structured error responses, audit logs, CSRF protection appropriate to the auth model, upload validation, rate limits, and staging/production environment separation. Protect contact data and honor an approved retention policy. Publishing should be atomic: draft edits must not appear on the public site before approval.

### Recommended integration sequence

1. **Extract and normalize all V6 content** from `build.py` into a versioned schema with stable IDs for pages, sections, services, industries, articles and media.
2. **Build the CMS backend** (database, authentication, authorization, content CRUD, secure uploads and publish jobs). Validate the API using automated tests before adding UI.
3. **Build the admin UI** on those stable endpoints, with a responsive section editor, media picker, SEO editor, inquiry view and global settings.
4. **Connect publishing** to the V6 rendering pipeline, preserve route redirects and canonical metadata, and support draft preview plus rollback.
5. **Test end to end:** edit every page element, publish and roll back, submit an inquiry to the configured recipient, check page SEO and accessibility, and verify mobile/desktop regressions.

## 11. Launch blockers and decision gates

- [ ] Obtain trademark/name and logo clearance in target markets; register the final domain.
- [ ] Validate target sub-sectors through actual customer conversations and confirm current delivery capacity.
- [ ] Approve diagnostic scope, statements of work, fees, exclusions and advisory-retainer commercial terms.
- [ ] Replace staging/disclaimer copy with verified leadership/team information; do not invent credentials, client logos, testimonials, or performance metrics.
- [ ] Supply lawyer-approved `legal/privacy.html` and `legal/terms.html` for the intended legal entity and jurisdictions.
- [ ] Configure Cloudflare Pages secrets: `RESEND_API_KEY`, `CONTACT_TO`, `CONTACT_FROM`; verify a real test inquiry reaches the destination inbox.
- [ ] Confirm security, data-handling, spam protection, consent and any analytics/cookie requirements.
- [ ] Run final real-host responsive QA, keyboard/accessibility checks, performance testing and SEO crawl checks.
- [ ] Enable the indexable production build **only after** all required gates are actually met.

The V6 builder deliberately requires explicit `PUBLIC_LAUNCH=1`, approved HTTPS `SITE_URL`, real `CONTACT_EMAIL`, `BRAND_LEGAL_CLEARED=1`, `LEGAL_PAGES_APPROVED=1`, `CONTACT_FORM_READY=1`, and approved privacy and terms HTML files before producing an indexable production build. These environment flags represent confirmed real-world approvals; do not bypass them solely to deploy.
